## Start with context

Check the domain in the top bar, the signed-in organisation and your account permissions. An alias can share a website environment with another domain. Portal sessions, WordPress accounts, mailboxes and database users each have separate access.

Record the exact message and time, then reload the current data. The general service status in the top bar is not an availability test for every individual website.

## Choose the right investigation

| Situation | Check first |
| --- | --- |
| Website will not open | [Active DNS zone and records](../dns-ssl/index.mdx), correct destination host and website status |
| Missing or expired certificate | [SSL and HTTPS](../dns-ssl/ssl.mdx), selected domain and public DNS |
| Email does not arrive | [Mail routing and MX](../dns-ssl/mail-routing.mdx), mailbox status, quota and [spam filters](../email/spam.mdx) |
| PHP error or blank page | [PHP version and extensions](../developers/php.mdx), [logs](../developers/logs.mdx) and recent code changes |
| Old page still shown | [Cache layers and exclusions](../performance/cache.mdx), then browser and external caches |
| Files inaccessible | Correct directory, [permissions](../files/permissions.mdx) and [FTP/SSH identity](../files/ssh.mdx) |
| Database connection fails | [Host, user, password and privileges](../databases/index.mdx) |
| Backup or restore fails | [Backup troubleshooting](../backups/troubleshooting.mdx) and current job status |

## A change was not confirmed

A timeout or unconfirmed-change message can mean the outcome is uncertain. The hosting service may already have received the change. Reload the relevant list or configuration before adding, deleting or starting a restore again.

If a VirtualHost change is still processing, let it finish and check the current configuration. Do not force the same change through multiple windows. For recovery operations, first check whether a restore is already running.

## A setting is missing

Availability depends on role, package, webserver and assigned services. A hidden or disabled option is not automatically a loading failure. Check the selected website’s permissions and services; ask the account owner or support if unsure.

## Help support investigate

Include the domain, feature, time, exact error, expected result and reproduction steps. A relevant log excerpt or screenshot helps after removing passwords, tokens, private keys, session links and personal data. State whether the website itself is affected or only the portal feature.

Preserve the current state before recovery where possible. Do not delete a database or website to solve a loading error. See also [frequently asked questions](./faq.mdx).
