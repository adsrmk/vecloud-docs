<Callout type="warning" title="ModSecurity is deprecated">
ModSecurity has been retired within veCloud since **May 2026** and is no longer used. This follows compatibility issues, including unintended blocking of internal WordPress requests and disruption of website functionality. This guide remains available as a reference for existing configurations.
</Callout>

Still seeing ModSecurity in an older guide or message? It refers to a previously used application firewall. You do not need to enable it or change its settings to use your website.

## A request is blocked

A `403` response does not automatically indicate ModSecurity. Application permissions, [file permissions](../files/permissions.mdx), [IP deny](./ip-deny.mdx) or an external proxy can also restrict access.

Check which URL and action are affected and whether other pages work. Repeat the action only if it will not cause duplicate orders or other unwanted changes.

## Ask support to investigate

Include the domain, exact URL, time and time zone, and error message. Explain whether it involves a form, WordPress administration action or internal request. Share only relevant log entries without passwords, tokens or sensitive form content.

The [PHP error log](../developers/logs.mdx) may add context, but does not list every access block. Let support investigate the cause, then test the affected website feature again.
