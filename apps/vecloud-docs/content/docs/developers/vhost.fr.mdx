Une application peut nécessiter une règle particulière du serveur web. veCloud gère la configuration VirtualHost personnalisée ; vous n’avez pas à ouvrir un éditeur interne.

## Commencer par les fonctions du site

Utilisez [Redirects](../dns-ssl/redirects.mdx) pour les redirections, [IP deny](../dns-ssl/ip-deny.mdx) pour les blocages et [Optimization](../performance/cache.mdx) pour le cache. Ces pages permettent de gérer vous-même les réglages pris en charge.

## Demander une règle supplémentaire

Précisez au support le domaine, le chemin URL et le résultat attendu. Décrivez le comportement actuel et souhaité et, si possible, joignez un lien vers les exigences de configuration de l’application. Un exemple de requête aide à vérifier le résultat.

Une configuration Nginx globale n’est pas forcément adaptée à un seul site. Laissez veCloud vérifier sa compatibilité avec les redirections, la sécurité et le cache existants. Ne partagez pas de fichiers contenant des mots de passe ou des clés.

## Après la modification

Convenez d’un moment pour tester. Après confirmation, vérifiez les pages, formulaires et redirections concernés. Si le résultat diffère de ce qui était prévu, indiquez l’URL exacte, l’heure et l’erreur. Demandez au support de vérifier ou d’annuler le changement ; évitez de modifier plusieurs réglages liés en même temps.
