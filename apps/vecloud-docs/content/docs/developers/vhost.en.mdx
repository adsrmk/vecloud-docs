An application may occasionally need a specific webserver rule. veCloud manages custom VirtualHost configuration; you do not need to open an internal editor.

## Start with the website features

Use [Redirects](../dns-ssl/redirects.mdx) for forwarding, [IP deny](../dns-ssl/ip-deny.mdx) for address blocks and [Optimization](../performance/cache.mdx) for caching. These pages let you manage the supported settings yourself.

## Request an additional rule

Tell support which domain and URL path are affected and what should happen. Describe the current and expected behaviour and, where possible, link to your application’s configuration requirements. A relevant example request helps verify the result.

A global Nginx configuration is not automatically suitable for one website. Let veCloud review how the rule fits existing redirects, security and caching. Do not share configuration files containing passwords or keys.

## After the change

Agree on a suitable time to test. After confirmation, check the affected pages, forms and redirects. If the result differs from what was agreed, report the exact URL, time and error. Ask support to review or reverse the change; avoid changing several related settings at once.
