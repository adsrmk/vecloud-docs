title: Manage and publish staging
description: Copy content to a new or existing website and distinguish this from converting staging.
icon: Globe
---

From a staging website, you can copy content or start using that environment for production. Decide on the intended result before choosing the corresponding action.

## Choose your destination

Open **Overview** on your staging website. If your plan and permissions allow it, **Publish staging** offers two ways to copy content. Use the separate **Promote to production** button when you want the staging website itself to become a production site.

| Action | Result |
| --- | --- |
| To a new website | Creates a separate website with copied content. |
| To an existing website | Copies to a selected website and can overwrite its content. |
| Promote to production | Converts the staging website itself to production. It does not copy content to another website. |

## Copy to a new website

1. Choose the new-website option in the copy menu.
2. If requested, select a subscription and a production or staging website type.
3. Enter the new domain or staging name. For staging, the panel shows the configured suffix.
4. Review WordPress search-and-replace when changing the domain.
5. Confirm the copy and follow its progress.

The new website uses the relevant website or staging allowance. A new domain may still need DNS and SSL before working publicly.

## Copy to an existing website

<Callout type="warning" title="Check the destination">
The selected destination can be overwritten. Preserve recent content and orders and create a destination backup first.
</Callout>

Select the destination. Review excluded paths, databases and database users. Check the options for deleting files that only exist at the destination and synchronizing the PHP version.

For WordPress, search-and-replace can update references from the old domain to the new one. Choose deliberately: a database can also contain absolute references you want to keep.

Review the selected options before choosing **Overwrite website**. **Delete destination files that do not exist on the source** can remove files that exist solely on the destination. Clear it if you need to keep those files. Also check whether the PHP version should change.

<PortalScreenshot name="staging-existing" alt="Source, existing destination and copy options" caption="The source is shown at the top. Verify Target website and the file and database options before overwriting." />

## Convert staging to production

**Promote to production** changes the staging website’s type and uses a regular website allowance. Its domain and content stay with the same website. To send content to an existing production website, use the existing-website copy option and check that destination.

<PortalScreenshot name="staging-promote" alt="Confirmation for converting staging to production" caption="The confirmation names the website that will become production and explains the regular website slot it uses." />

## After copying

Check the destination, important pages, administration area, forms and database connection. If the outcome is unclear, review progress and the website list before starting another copy.
